# GameWithFriends

一个 HTML 前端与 Python 后端分离的好友游戏项目，提供管理员创建账号、登录、台球房间和扑克牌抽号功能。

## 运行

需要 Python 3.9 或更高版本，无需安装第三方依赖。在项目根目录运行：

```powershell
python backend\main.py
```

然后在本机浏览器中打开 <http://127.0.0.1:8000>。服务同时监听 IPv4 和 IPv6，IPv6 本机地址可用 <http://[::1]:8000> 测试。同一局域网的朋友可以使用运行服务电脑的局域网 IPv4 或 IPv6 地址和端口 `8000` 访问（Windows 可用 `ipconfig` 查看地址，并按需允许路由器 IPv6 入站规则和 Windows 防火墙通行）。IPv6 地址放在网址中时必须用方括号，例如 `http://[240e:...]:8000`。按 `Ctrl+C` 停止服务。

## 目录

```text
frontend\index.html   页面结构
frontend\index.css    页面样式
frontend\index.js     页面交互与房间状态同步
backend\main.py       Python HTTP API 与本地开发服务器
backend\users.db      首次启动时自动创建的 SQLite 数据库
```

用户密码使用随机盐和 PBKDF2-HMAC-SHA256 哈希保存，不会以明文写入数据库。普通用户不能自行注册；管理员登录后可创建用户账号。管理员账号为 `GameAdmin`，初始密码为 `12345678990`。历史版本中与管理员重名的普通账号 `HuXuan` 已恢复为普通用户，并保留其账号及房间关联。该固定管理员凭据仅适合可信局域网开发测试，不要将此配置的服务暴露到公网。

台球支持创建/加入房间、设置本局目标人数、玩家准备、房主开局、每位玩家抽取 1–15 张牌以及裁判观战；首次抽牌后，玩家还可以逐张从剩余牌库继续抽牌。对局中只有房主可以重新开局，清空全房间手牌和进球状态并回到抽牌阶段。玩家席位坐满且全部准备后，房主才能开始游戏。房间号由创建日期和当天的房间序号组成；房间和抽牌状态保存在 SQLite 中，页面每 0.05 秒同步一次房间状态，且避免前一次状态请求未结束时重复发起请求。普通玩家只能看到自己的牌，裁判能看到房间内所有玩家的抽牌结果。所有活跃玩家至少抽到一张牌后，房间状态会显示“抽牌已完成”；否则显示“抽牌进行中”。玩家可点击自己抽到的牌，裁判可点击任意玩家的牌来切换进球状态；所有手牌连续展示，已进球的牌以颜色和“已进球”标记区分，再次点击可撤销。扑克牌包含四种花色和大小王，抽取的实体牌不会重复；相同点数的不同花色对应相同台球号码。房间成员可主动离开；曾经加入过的玩家可以通过同一房间号重新加入仍开放的房间；玩家在等待阶段重新加入后需要重新准备，对局中的原玩家可恢复房间并保留手牌和分数；等待中的房主离开时会将房主移交给下一位玩家。当所有玩家和裁判都离开房间后，房间会关闭，此后任何人（包括原成员）都不能再加入。对局开始后，玩家状态显示为“对局中”。麻将房间和实际台球物理对局暂未实现。

每位玩家的分数会同步显示给全房间成员；玩家只能修改自己的分数，裁判可以修改任意玩家的分数。分数输入后需点击“确认分数”才会保存并同步给其他成员，未确认的输入只保留在当前设备。保存采用版本号乐观并发控制；若其他成员先修改了同一分数，旧版本提交会被拒绝并显示最新分数。分数为 `-1,000,000,000` 到 `1,000,000,000` 之间的整数，并保存在 SQLite 中。对局中，所有成员都能在玩家用户名旁看到该玩家尚未进球的手牌数量，该数量会随进球状态同步更新。

点击“从剩余牌库再抽一张”抽到的牌，会在牌面显示对应台球号码并在右上角标注“抽”；开局首次抽取的牌只显示台球号码，不带此标识。裁判视图中也会保留该标识。

当前开发服务器使用 HTTP，适用于本机或可信局域网测试；不要直接暴露到公网，公网部署应使用 HTTPS 和正式的应用服务器。
